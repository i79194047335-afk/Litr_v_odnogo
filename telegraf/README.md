# Телеграф

Следит за официальным каналом API-апдейтов Lighter в Telegram
(`@lighter_api_updates`). Раз в сутки читает публичное превью канала, берёт
посты новее последнего виденного и просит DeepSeek разобрать каждый.

Один шелл-скрипт плюс парсер на Python. Claude в рантайме не участвует.

## Зачем отдельно от Архивариуса

Архивариус смотрит `apidocs.lighter.xyz` и видит только то, что доехало до
документации. Часть изменений анонсируется в канале и в доках не появляется
вовсе или появляется позже.

Измерение, а не предположение: 23 июля в канале анонсирован эндпоинт
`accountOrders` (статус до 20 `client_order_index` за запрос). Архивариус его
не заметил. Там же 21 июля — параметр `market_ids` у `positionFunding`.

## Как работает

```
t.me/s/lighter_api_updates ──curl──> HTML
                                     │
                                     ├─ parse_posts.py ──> JSONL по посту
                                     ├─ отсечь всё <= last_post_id
                                     │   └─ ничего нового? выход, БЕЗ модели
                                     └─ новые ──> DeepSeek ──> knowledge/
```

Авторизация не нужна: `t.me/s/<канал>` отдаёт посты прямо в HTML. Это
единственная причина, по которой Телеграф вообще возможен как шелл-агент —
Discord так читать нельзя, там гейт `verify` и личный токен.

Что оказалось важнее: Discord `#api-updates` сверен построчно с этим каналом
2026-08-03 — **различий ноль**, тот же автор, тот же текст. Так что Телеграф
не «дешёвая замена» Discord, а полный его эквивалент по этому потоку.

**Состояние — один файл** `state/last_post_id` с номером последнего
разобранного поста. Номера в Telegram монотонные, поэтому диффа не нужно:
пост либо новее отметки, либо нет.

**Первый прогон** только ставит отметку и не вызывает модель: история канала
уже случилась, а токены стоят денег. В день без новых постов вызовов тоже
ноль.

## Настройка

Ключ DeepSeek — там же, где у Архивариуса: `~/.deepseek_key` (или
`DEEPSEEK_API_KEY`, или `.env` проекта). Канал доставки — `scripts/notify.sh`,
ключи в `~/.telegram_key` и `~/.telegram_chat`.

Из системного нужен `jq` и `python3`.

## Запуск

```bash
telegraf/telegraf.sh
```

Раз в сутки через cron, со сдвигом от Архивариуса, чтобы не сойтись в одну
минуту:

```cron
30 6 * * * cd /root/projects/Litr_v_odnogo && telegraf/telegraf.sh >> telegraf/logs/cron.log 2>&1
```

## Что где лежит

| Путь | Что это | В git |
|---|---|---|
| `telegraf.sh` | агент | да |
| `parse_posts.py` | разбор HTML в JSONL, отдельная тулза | да |
| `knowledge/updates.md` | разбор прозой — для человека | да |
| `knowledge/events.jsonl` | то же строками JSON — для машин | да |
| `state/last_post_id` | номер последнего разобранного поста | нет |
| `logs/run.log` | лог прогонов | нет |

## Как читать результат

```bash
jq -r 'select(.breaking) | "\(.posted[:10]) \(.summary)"' telegraf/knowledge/events.jsonl
jq -r 'select(.kind=="api") | .highlights[]'               telegraf/knowledge/events.jsonl
jq -r '.kind' telegraf/knowledge/events.jsonl | sort | uniq -c
```

Проверить пересказ модели — рядом лежит исходный текст поста:

```bash
jq -r 'select(.post_id==154) | .evidence' telegraf/knowledge/events.jsonl
```

Поля: `v`, `ts`, `source`, `channel`, `post_id`, `posted`, `url`, `kind`,
`breaking`, `highlights[]`, `summary`, `evidence`. Плюс `backfill: true` у
записей, полученных перемоткой отметки, а не новым постом.

`v` — версия схемы, сейчас `1`. Потребитель обязан её проверять.

`kind` — `api`, `limits`, `behavior`, `release`, `market`, `other`. Если модель
ответила прозой, `kind` будет `?`, а текст всё равно сохранится.

## Уведомления

При `breaking: true` шлёт в Telegram через `scripts/notify.sh` с именем
отправителя `[telegraf]`. Обычные релизы и листинги молчат: алерт на каждый
пост перестают читать.

## Тесты

```bash
telegraf/test_telegraf.sh          # 17, агент целиком, сети не требует
.venv/bin/python -m pytest tests/test_parse_posts.py -q   # 15, парсер
```

Парсер вынесен в отдельную тулзу и тестируется отдельно, потому что он —
единственное место здесь, где можно ошибиться незаметно: он превращает разметку
в предложения, которые модель потом пересказывает как факт.

**Что уже поймали тесты.** Реальные посты 138 и 141 несут цитату того поста, на
который отвечают: на первой странице 20 постов и 22 текстовых блока. Наивный
парсер выдал бы чужую цитату за новый анонс.

**И ещё один дефект, найденный при разработке:** при ответе модели прозой
`jq .highlights` по пустому входу завершается успешно и печатает ничего,
из-за чего `--argjson hl ""` роняет jq и событие не пишется — при том, что
проза уже легла в `updates.md`. Выходы расходились молча. Тот же дефект нашёлся
в Архивариусе (это его код) и исправлен там же; оба теперь имеют тест.

## Поведение при сбоях

- Канал недоступен → прогон прерывается, отметка не двигается.
- Страница разобралась в ноль постов → прерывается с явным сообщением, что это
  смена формата или поломка парсера, **а не** тишина в канале.
- Модель не ответила или выродилась в повтор → пост не записывается, отметка
  остаётся перед ним, следующий прогон берёт его снова.
- Ответ не JSON → текст сохраняется, `kind` становится `?`, событие пишется.
- Новых постов больше 25 за прогон → остановка: либо взрыв активности, либо
  потерянная отметка, и то и другое стоит увидеть до траты токенов.
