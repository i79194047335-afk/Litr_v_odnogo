# Архивариус

Следит за документацией Lighter API. Раз в сутки обходит все страницы,
сравнивает со снимком с прошлого прогона и только для изменившихся просит
DeepSeek описать, что поменялось. Результат копится в
`knowledge/api_changelog.md`.

Один шелл-скрипт, ~300 строк. Claude в рантайме не участвует.

## Зачем

Документация декса меняется постоянно, а замечаешь это обычно тогда, когда
что-то уже сломалось. Архивариус превращает «надо бы как-нибудь перечитать
доки» в готовый список изменений с датами.

## Как работает

```
llms.txt ──curl──> список 103 страниц
                   │
                   ├─ curl каждую страницу
                   ├─ cmp со снимком прошлого прогона
                   │   └─ совпало? дальше, БЕЗ обращения к модели
                   └─ изменилось? ──jq──> DeepSeek ──> knowledge/api_changelog.md
```

Инструменты: `curl`, `awk`, `cmp`, `sha256sum`, `jq`. Никаких зависимостей
языка, никакого venv — то, что есть в системе.

**Первый прогон** только снимает базовый слепок и не делает ни одного вызова
модели: сравнивать не с чем. Реальная работа начинается со второго прогона.
В обычный день, когда доки не менялись, вызовов модели тоже **ноль** — только
сравнение хэшей.

## Настройка

Нужен ключ DeepSeek. Скрипт ищет его в трёх местах, в таком порядке:

1. переменная окружения `DEEPSEEK_API_KEY` (удобно для разовых запусков);
2. файл `~/.deepseek_key` — **основной способ**;
3. `.env` в корне проекта (запасной вариант).

Ключ живёт в отдельном файле, а не в `.env` проекта: его переиспользуют все
будущие агенты, и он не размножается копиями по репозиториям.

```bash
umask 077 && jq -r '.mcpServers["cheap-llm"].env.DEEPSEEK_API_KEY' /root/.claude.json \
  | tr -d '\n' > ~/.deepseek_key && chmod 600 ~/.deepseek_key
```

Путь можно переопределить переменной `DEEPSEEK_KEY_FILE`.

Из системных пакетов нужен только `jq` (`apt-get install jq`).

## Запуск

```bash
archivarius/archivarius.sh
```

Раз в сутки через cron:

```cron
0 6 * * * cd /root/projects/Litr_v_odnogo && archivarius/archivarius.sh >> archivarius/logs/cron.log 2>&1
```

Ключ подхватится из `~/.deepseek_key` сам — cron ничего передавать не нужно.
Учтите только, что у cron свой `$HOME`: если запускать не от того же
пользователя, задайте путь явно через `DEEPSEEK_KEY_FILE=/root/.deepseek_key`.

## Что где лежит

| Путь | Что это | В git |
|---|---|---|
| `archivarius.sh` | весь агент | да |
| `knowledge/api_changelog.md` | изменения прозой — для человека | да |
| `knowledge/events.jsonl` | те же изменения строками JSON — для машин | да |
| `state/snapshots/` | прошлые версии страниц для сравнения (~900 КБ) | нет |
| `logs/run.log` | лог прогонов | нет |

Состояние — это сами снимки: есть файл, значит страницу уже видели. Отдельной
базы нет и не нужно.

## Как читать результат

Прозой, свежее сверху:

```bash
head -40 knowledge/api_changelog.md
```

Потоком, для фильтров и следующих агентов — по одному JSON-объекту на строку:

```bash
jq -r 'select(.breaking) | .title'                    knowledge/events.jsonl
jq -r 'select(.kind=="limits") | .highlights[]'       knowledge/events.jsonl
jq -r 'select(.kind!="cosmetic") | "\(.ts[:10]) \(.title)"' knowledge/events.jsonl
jq -r '.kind' knowledge/events.jsonl | sort | uniq -c   # что меняется чаще всего
```

Проверить, не выдумала ли модель пересказ — рядом лежит сам дифф:

```bash
jq -r 'select(.kind=="limits") | .evidence' knowledge/events.jsonl
```

Поля события: `v`, `ts`, `source`, `url`, `title`, `section`, `change`
(«изменена» / «новая страница»), `kind`, `breaking`, `highlights[]`, `summary`,
`evidence`.

`v` — версия схемы, сейчас `1`. Потребитель обязан её проверять: формат будет
меняться, и молчаливое чтение чужой версии — это разбор мусора под видом
данных. Фильтр: `jq 'select(.v == 1)'`.

`kind` — один из: `api` (эндпоинты, параметры, поля), `limits` (лимиты, квоты,
тарифы), `behavior` (правила и поведение), `docs` (только текст и примеры),
`cosmetic` (опечатки, форматирование). Если модель ответила прозой вместо
JSON, `kind` будет `?`, а текст всё равно сохранится в `summary`.

`evidence` — первые 40 строк унифицированного диффа, по которому модель делала
вывод. Снимки лежат вне git и старый затирается новым, поэтому без этого поля
ни одно утверждение в журнале потом не перепроверить. У новых страниц оно
пустое — сравнивать не с чем.

Внимание: **ни одно из 103 событий, лежащих в файле сейчас, его не несёт** —
все они записаны 31 июля, до появления поля. Первые события с `evidence`
появятся при следующей правке документации на стороне Lighter.

## Модель

`deepseek-v4-flash` — дешёвый тир. Архивариус не рассуждает о стратегии, он
читает и пересказывает.

Как показал себя на единственном настоящем прогоне (31 июля, Lighter добавил
строку про `llms.txt` на все 103 страницы):

- 93 страницы из 103 разобраны верно — правка классифицирована как
  несущественная, `breaking: false` везде, ни одной ложной тревоги;
- на 10 страницах ответ пришёл негодным: один валидный JSON за мусорным
  префиксом, три — вырождение в повтор одного слова на ~18 КБ, остальные прозой.

То есть дешёвый тир справляется, но примерно каждый десятый ответ приходится
отбрасывать и повторять. Отсюда детектор вырождения и отказ писать в базу
неразобранное — см. «Поведение при сбоях».

Если начнёт смазывать важное — поменять `MODEL` на `deepseek-v4-pro`.

## Тесты

```bash
archivarius/test_archivarius.sh
```

Сети и ключа не требуют: индекс и страницы отдаёт локальный http-сервер,
ответы модели подставляются заглушками. ~30 секунд.

Проверяются режимы отказа, а не happy path — агент дописывает в постоянную
базу, и тихий баг здесь не падает, а портит запись. Четыре проверки из
пятнадцати взяты из поломок, которые уже случались: три — из разбора базы
после прогона 31 июля, одна — из падения парсера индекса на mawk.

Логика (разбор ответа, пороги детектора) **извлекается из самого агента**, а не
дублируется в тесте. Проверено намеренными поломками: копия логики оставляла
тесты зелёными на сломанном агенте, извлечение — ловит.

## Правило: тесты не пишут в knowledge/

Проверять агента на подменённых снимках можно и нужно, но **только на копии
`state/`**. Всё, что попадает в `knowledge/`, должно быть настоящим
наблюдением.

Причина не теоретическая. 30 июля снимок `rate-limits` дважды правился вручную,
чтобы проверить пересказ, и обе выдумки записались в журнал как реальные
изменения лимита — рядом с настоящими наблюдениями и неотличимо от них. Живая
страница отдаёт `60 requests per rolling minute` с 10 июля и не менялась.
Записи удалены 31 июля, в шапке журнала стоит маркер.

Как правильно:

```bash
cp -r archivarius/state /tmp/arch-test-state
# правим снимки в /tmp/arch-test-state, гоняем агента на копии
```

Если синтетика всё же должна попасть в `knowledge/` — только с полем
`"synthetic": true` в событии, чтобы её можно было отфильтровать.

## Поведение при сбоях

- Индекс недоступен → прогон прерывается, снимки не трогаются.
- Индекс распарсился в 0 страниц (сменился формат) → прерывается, чтобы не
  затереть состояние пустотой.
- Отдельная страница не открылась → считается в `не открылось`, остальные идут.
- Модель не ответила → в журнал попадает пометка, а снимок откатывается на
  прежний, чтобы следующий прогон увидел страницу изменённой и попробовал снова.
- Ответ пришёл не JSON-ом → текст сохраняется как есть, `kind` становится `?`,
  событие в JSONL всё равно пишется (иначе проза и поток расходятся).
- Ответ выродился в повтор одного слова → отбрасывается целиком, снимок
  откатывается, страница перепроверяется на следующем прогоне. Модель на это
  срывается: 31 июля так испортились 3 страницы из 103, по ~18 КБ мусора каждая.

## Уведомления

При `breaking: true` Архивариус пишет в Telegram через `scripts/notify.sh` —
иначе журнал надо пойти и открыть, а агент на сервере просто молчит.

Косметика и обычные изменения уведомления не вызывают: алерт, приходящий на
каждую опечатку, перестают читать.

Ключи — `~/.telegram_key` и `~/.telegram_chat` (права 600), рядом с
`~/.deepseek_key` и по той же причине: их переиспользуют все следующие агенты.
Бот пока общий с `funding-watcher`, поэтому каждое сообщение начинается с имени
отправителя — `[archivarius]`.

Проверить канал отдельно от агента:

```bash
scripts/notify.sh archivarius "проверка связи"
```

Коды возврата: `0` доставлено, `2` не настроено, `3` Telegram отказал или сеть.
Провал доставки не роняет прогон, но попадает в лог как `WARN` — молчание
канала иначе неотличимо от «изменений не было».
