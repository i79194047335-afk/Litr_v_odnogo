HYPOTHESIS: `swing_confirm_bars = 2` is the optimal value for the swing tracker.
Widening it was tested on real data and made backtest results worse, so the
parameter does not need to be swept and 2 can be kept as the fixed default in
all further work.

VERDICT: REFUTED

The claim has two limbs and both fail, for different reasons:
  (a) "widening was tested on real data and made results worse" — refuted as a
      statement about this repo: no such measurement exists in it.
  (b) "therefore 2 is optimal and needs no sweep" — does not follow even if (a)
      were true, because the baseline it would be optimal within is negative.
Strictly, "2 is optimal" on its own is UNTESTABLE as written (no metric, no
split, no cost assumption named), but the hypothesis as stated asserts a
measurement that did not happen, so REFUTED is the honest label.

UNSTATED ASSUMPTIONS:
  - That "optimal" is defined at all. No metric, no day split, no cost
    assumption is named. ACCEPTANCE_SWEEP ran with costs zero, so any optimum
    inherited from that harness is a zero-cost optimum, which is not the live
    objective.
  - That the response to N is monotone, so trying one wider value rules out all
    N > 2. Even a single wider run — which is more than the record shows — would
    not do that.
  - That only widening is on the table. `SwingTracker` validates `N >= 1`, so
    `N = 1` exists and is never mentioned anywhere. "2 is optimal" was never
    even compared downward.
  - That `swing_confirm_bars` is separable from `range_size`. Both set scale: at
    `range_size=15.3`, N=2 means a 5-range-bar window ≈ 76.5 points. Sweeping
    one with the other frozen assumes away a 2-D interaction, and the frozen one
    is itself an uncalibrated heuristic.
  - That BTC generalizes. Every recorded backtest is BTC.

ALTERNATIVE EXPLANATIONS (for the "widening made it worse" observation, if it
was ever really seen):
  - Pure exit latency, not swing quality. Widening N delays every swing
    confirmation by N bars, so the reversal exit fires later; with the stop
    distance unchanged, more trades reach the stop before the exit can fire.
    That would degrade results while telling us nothing about how mature a swing
    point should be.
  - Sample-size collapse mistaken for edge decay. Larger N confirms fewer swings
    → fewer signals → fewer trades and wider error bars. At the recorded
    baseline t-stats (−2.95 in-sample, −0.86 out-of-sample) the system already
    sits near noise; a modest drop in trade count flips the sign of a mean this
    small without any change in underlying edge.
  - One draw at one scale. If "worse" was seen on in-sample days only, it is a
    single observation — which is exactly what `CONTEXT.md:1426-1430` already
    concluded about every negative result in this project.
  - Optimality inside a loss. The baseline is −0.50 bps in-sample. "Worse than a
    losing configuration" cannot establish optimality; at best it identifies the
    least-bad of about two tried points of a strategy with no demonstrated edge.

ARITHMETIC: recomputed independently, the two derivable numbers agree.

bars minimum", and the confirmation lag is N = 2 bars. Nothing else in the
hypothesis is arithmetic — there are no sweep results to recompute, which is
itself the finding.
