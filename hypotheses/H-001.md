# H-001: swing_confirm_bars=2 is optimal

Status: open
Proposed: 2026-07-28
Proposer: Claude (protocol shakedown)

## Claim

`swing_confirm_bars = 2` is the optimal value for the swing tracker.
Widening it was tested on real data and made backtest results worse, so the
parameter does not need to be swept and 2 can be kept as the fixed default in
all further work.

## Notes for the falsifier

Scope facts only:

- `swing_confirm_bars` controls how mature a swing *point* must be: a candidate
  bar is confirmed as a swing when it is more extreme than the `N` bars before
  AND the `N` bars after it, so the tracker's window is `2N + 1` bars and a
  swing is always identified `N` bars late.
- It is a distinct parameter from `acceptance_bars`, which controls how many
  bars a swing-structure *break* must hold before a reversal exit fires.
  `acceptance_bars` was swept in July 2026; `swing_confirm_bars` is the other
  knob.
- Every recorded backtest in this project ran at `swing_confirm_bars=2` and
  `range_size=15.3`.
- The repo has no `docs/` file dedicated to a `swing_confirm_bars` sweep, and no
  results table with `swing_confirm_bars` as a column.
- Search the whole PROJECT RECORD for provenance; some numbers above may trace
  to a real measurement and others may not.
